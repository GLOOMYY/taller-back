# Clean Code

## Reglas aceptadas

- Una unidad tiene responsabilidad coherente y nombre que revela intención.
- Preferir flujo directo y explícito sobre indirección o metaprogramación innecesaria.
- Eliminar duplicación de conocimiento; no abstraer coincidencias superficiales.
- Mantener reglas en Domain/Application y traducciones en adaptadores.
- Evitar parámetros booleanos opacos, comentarios que compensen nombres pobres y clases “utilidad” sin cohesión.
- Hacer visibles el contexto tenant, los errores y los efectos laterales.
- Dejar el área modificada igual o más clara, sin refactorizaciones fuera de alcance.

Las métricas de complejidad concretas están **Pendientes**; la revisión evalúa comprensión y riesgo, no solo números.
