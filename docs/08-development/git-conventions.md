# Convenciones Git

## Propuestas

- Cambios pequeños, coherentes y revisables.
- Commits con intención clara; no mezclar refactorizaciones ajenas.
- Ramas y mensajes deben referir tarea/requisito cuando exista.
- Pull request describe alcance, decisiones, pruebas, riesgo tenant y documentación.
- No reescribir historia compartida ni incluir secretos o artefactos locales.
- Toda excepción arquitectónica requiere decisión trazable.

Formato de ramas/commits, estrategia de integración, aprobaciones y release tagging están **Pendientes**.
